# Changelog

All notable changes to this project are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Added
- `theoria`: the `Gallery` component (sidebar tree of stories, stage, live controls with a Reset button that puts every arg back to its default, show-code panel, Markdown autodocs, and a URL for each story, `?story=<full name>`, which opens it and which selecting a story writes), `Story` with `Story::new`, `with_description` (a Markdown description for a story built by hand, shown in the docs panel), `view` (the story's body drawn with its args' current values, so a leptotes test can check what an arg feeds), and `arg` (one arg, by name), `Stories` (what a crate's aggregator returns, with `gallery()` and, under `csr`, `mount()`, which also logs a panic to the browser console with the JavaScript stack that reached it), `Arg` and `ArgControl` (a story's args: `Arg::new` builds one over a signal and picks its control by the signal's type, and `Arg::group` one over other args, drawn under its name; each arg has a name, its type as written, its control, with `ChoiceControl` for a choice's options and selection and `GroupControl` for a group's args, a Markdown description set with `with_description`, `switch` (the on/off switch of an `Option` of a struct), and `reset`, which puts the signal back to the value it held when the arg was built, writing only an arg that was edited), `StoryArg` (the trait of types a `#[story]` parameter can have, each picking its control, implemented outside theoria only through `#[derive(StoryArg)]`), `Bounded` (a number with optional bounds and step, drawn with a slider when it has both bounds), `Color` (any CSS color as text, drawn as a swatch and a text field), `Choice<T>` (one of a fixed list of labelled values, drawn as a menu), and the selected story kept in the URL and in `localStorage` under the `csr` feature
- `theoria-macros`: `#[story]`, which turns a function's `bool`, `f64`, `String`, `Bounded`, `Color`, and `Choice<T>` parameters into live controls and captures its body source and doc comment; a parameter typed `Signal<T>` over one of them gets the arg's signal, so an edit to it redraws only what reads it instead of running the whole body again; a key in the attribute that names no parameter is a compile error; a parameter written as a raw identifier (`r#type`) is named without the prefix, in the panel and for `Story::arg`; and `#[derive(StoryArg)]`, which makes a struct of named fields one arg with a control per field, picked by the field's type (a `&'static str` is a text box, kept once per distinct text it is edited to), with each field's doc comment shown beside its control, a field whose type also derives `StoryArg` drawn as a group of its own fields under the field's name, an `Option` of such a struct (as a field or a parameter, the struct also `Default`) drawn as that group with a switch, where off is `None` and on again brings back the fields as they were left, `#[story_arg(color)]` on a `&'static str` field or on the struct for every one, `#[story_arg(skip)]` for a field kept at its default, and a field of any other type a compile error at the field
- `theoria-cli`: the `theoria` binary, whose `serve`, `build`, and `generate` write a Trunk app under `target/theoria/gallery` from a `theoria.toml` and run Trunk on it, rebuilding on source edits; the app only calls `mount()` on the aggregator's `Stories`, so it shares one theoria and one Leptos with the stories wherever they come from, and each run copies the `Cargo.lock` of the stories crate's workspace into it, so the gallery builds on the versions that lockfile records; `theoria_cli::run`, which is all the binary's `main` calls, so a workspace with stories can build the CLI as a three-line package of its own, from the theoria commit in its `Cargo.lock`
